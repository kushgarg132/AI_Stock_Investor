topic: Expand intraday trading strategies beyond volume_surge
updated: 2026-09-08T19:43
---

- (decision) Add 3 new intraday strategies to reach parity with 5 longterm strategies: VWAP Reversion (CAP-1), Opening Range Breakout (CAP-2), RSI Momentum Scalp (CAP-3). Chosen because they reuse existing Indicators.vwap/rsi/atr (backend/components/quant/indicators.py) which are implemented but currently unused by any Strategy subclass -- no new indicator math needed.
- (constraint) Must follow TokenResolvingStrategy pattern (backend/strategies/base.py) and StrategySpec/Intent contracts (backend/engine/protocols.py, backend/core/models.py) -- same shape as volume_surge.py, mode=INTRADAY, timeframe=5m.
- (constraint) No I/O, no wall-clock reads (datetime.now()), no network calls inside strategy modules -- enforced by existing tests backend/tests/test_no_datetime_now.py and test_no_network_in_strategies.py; new strategy files must pass both.
- (constraint) Each new strategy must be backtested via the existing engine (backend/engine/backtest.py::run_backtest) on historical data before being wired into build_default_strategies() (backend/strategies/registry.py) and thus before it can surface live suggestions through the approval flow -- user decision: backtest gate is required, real money is on the line.
- (constraint) Every reason_code, stop_hint and target_hint must be justified by the strategy's own logic (per Intent's __post_init__ contract in backend/core/models.py) -- no bare/unexplained signals.
- (capability) CAP-1 VWAP Reversion: intent=flag intraday mean-reversion trades when price deviates >X% from session VWAP and starts reverting; success=strategy emits BUY/SELL Intent with reason_code vwap_reversion, backtest win-rate and drawdown reviewed and accepted by user before live wiring.
- (capability) CAP-2 Opening Range Breakout: intent=flag breakout trades when price clears the first N-minute high/low range with volume confirmation; success=strategy emits BUY/SELL Intent with reason_code orb_breakout, backtest reviewed and accepted before live wiring.
- (capability) CAP-3 RSI Momentum Scalp: intent=flag short-duration momentum trades on RSI crossing overbought/oversold thresholds with trend confirmation; success=strategy emits BUY/SELL Intent with reason_code rsi_momentum_scalp, backtest reviewed and accepted before live wiring.
- (non-goal) Not adding a 4th+ intraday strategy this round; not touching longterm strategies; not changing the approval/suggestion UI; not adding new indicator math beyond what Indicators already provides (rsi/vwap/atr).
- (assumption) Opening range window defaults to first 15 minutes of the trading session (09:15-09:30 IST, NSE) -- standard ORB convention, not explicitly confirmed by user.
- (question) Exact VWAP-deviation threshold, RSI overbought/oversold levels, and ORB range window are left to implementation-time backtesting/tuning rather than fixed upfront -- open question for whoever backtests: what thresholds pass the win-rate/drawdown bar.
- (event) Self-validate pass 1 (coherence, rules 1-6,8): PASS. Pass 2 (preservation): PASS, every memlog decision/constraint/capability/non-goal landed in SPEC.md, no wrapper-only drops. SPEC.md finalized.
- (event) Backtest run (59d real NSE 5m data, RELIANCE/TCS/INFY/HDFCBANK/ICICIBANK) via run_backtest: volume_surge baseline 279 trades/48.55% win/PF 1.01 (sanity check, matches shipped behavior). vwap_reversion 2 trades/100% win but PF undefined (0 losses) -- sample too thin to judge, DEVIATION_THRESHOLD too strict. orb_breakout 218 trades/50.56% win/PF 0.93/PnL -19460 -- net loser as tuned. rsi_momentum_scalp 6 trades/25% win/PF 0.20/PnL -17768 -- net loser, thin sample. Verdict: none accepted yet, none wired into build_default_strategies(); backtest gate constraint holds. Presented to user for iterate-vs-stop decision.
- (event) Backtest v2 (tuned thresholds) on same 59d dataset: vwap_reversion still 2 trades/100% win (thin, threshold wasn't the binding constraint -- single-bar reversion check is inherently rare). orb_breakout tightened filters cut 218->6 trades, PF improved 0.93->0.17 but still net loser (PnL -6589) -- the original 218-trade sample is large enough to say ORB has no edge on this universe/timeframe as designed, not just noise. rsi_momentum_scalp cut 6->2 trades, both losers (0% win). Verdict: further threshold tuning against this single 59-day window risks overfitting noise, not finding real edge -- stopping the tuning loop here. None of the 3 wired into build_default_strategies(); recommending against shipping without either a longer/walk-forward-validated backtest or accepting these as unvalidated scaffolding.
